# Niblit r6.1 shutdown verification

**Root cause evidence.** The historical r6 package closed its ports and child processes but required test-owned termination after 150.9 seconds. A fresh r6 package run exited in 52.7 seconds, so the timeout was intermittent. The source trace captured two SLSA producers and their phase executors during active DuckDuckGo search and local BERT embedding. The old phase wrapper called shutdown(wait=False, cancel_futures=True) when its caller timed out. Running futures cannot be cancelled by that call. The controlled reproducer captured the Python main thread in concurrent.futures.thread._python_exit, waiting to join the still-running research executor. The original hung packaged process had no Python stack capture, so that exact stack is confirmed for the reproduced mechanism rather than inferred as direct evidence from the historical process.

**Changes.** SelfIdeaImplementation no longer starts an unmanaged research loop in its constructor. The existing explicit learning controls remain available. SLSA propagates its stop event into the research phases. Phase workers check cancellation before new provider and persistence work and bound research network calls. The phase wrapper waits for the owned executor to finish. Core stops its learning producers, API, async tasks and default executor, memory projection and autosave workers, then checkpoints the database. The executable also closes its command sidecar and releases owned managed processes. Cleanup events carry component names, state and elapsed time.

**Background evidence.** Both isolated runs reached the Core API, Cloud, Lean and strategy-worker listeners, survived an HTTP client disconnect with no desktop child, and refused a duplicate Core. The two Windows Ctrl+Break shutdowns exited with code 0 after 10.7 and 10.6 seconds. Neither required forced termination. Both left zero tracked descendants and no isolated listeners. The second run reused the first run's isolated durable files, which remained readable. No pre-existing user-owned Core, Cloud, Lean, Freqtrade or llama.cpp process was found at the initial check. Existing attach/ownership behavior was covered by the regression suite.

**Tests and package.** The scoped suite passed 105 tests. The five focused cancellation and SLSA tests passed again after the last worker-stop change. Both normal CLI startup/exit cycles and the frozen broker-double self-test passed. Frozen preflight verified 14 required files and 18 frozen modules. All four sidecars match the previous r6 binaries. Keep the full one-folder release together.

**Trading safety.** The existing ordinary stop, emergency stop and Core shutdown paths remain separate. Trading tests covered revocation, emergency latching, restart quarantine, expiry, reconciliation and risk enforcement with broker doubles. No actual demo or real-money orders were placed. No broker credentials or permissions changed. The isolated lifecycle runs used the existing no-generation and no-execution settings. Active native model or real broker workloads at shutdown were not exercised.
