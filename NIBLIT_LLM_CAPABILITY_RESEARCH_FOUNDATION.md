## EXECUTIVE VERDICT

Niblit does **not** need a new capability, tool, or research system built from
scratch. The intended LLM-supervised architecture **already exists at ~70–80%**
across the repositories under different names. This phase proved the inference
bridge end-to-end, found and fixed two real convergence defects in the
Core↔Cloud path, and produced the authority matrix below. The recommended next
step is *wiring*, not building: expose `AIOSLayerRegistry` + `NiblitToolExecutor`
+ `phased_research_engine` to the local LLM through Cloud's OpenAI
function-calling loop.

## CONVERGENCE DEFECTS FOUND THIS PHASE

1. **FIXED — Cloud preflight overrode explicit model selection.**
   `_orchestrator_mod.get_model_orchestrator().route()` rerouted *every*
   request when >1 model was available — including explicitly requested ones —
   based on latency EMA (qwen3B's slow cold load penalized it permanently).
   Fix (`app/main.py`): `explicit_selection = bool(payload.model or path_model)`;
   orchestrator rerouting now applies only when no model was explicitly chosen.
   Verified live: both `model=local` and `model=qwen2.5-coder-3b` now return
   `"model": "qwen2.5-coder-3b"`.

## KEY GAP FOR CAPABILITY WORK

QwenLocalBrain.generate_with_tools() is deprecated and DROPS the tools
parameter - it forwards plain chat to Cloud. Until Cloud /v1/chat/completions
passthrough supports OpenAI tools/tool_choice (llama.cpp tool-call parsing for
qwen2.5 templates), the LLM cannot emit structured tool calls. This is the
single highest-leverage implementation item: one endpoint upgrade unlocks the
existing NiblitToolExecutor capability layer.

## DEFECTS found + fixed via the pipeline (both newline/fidelity class)
1. FIXED - FilesystemManager.write_file_safe corrupted CRLF files:
   Path.write_text applies universal-newline translation, so `\n` in content
   became `\r\n` on Windows; a CRLF file rewritten through it doubled every
   CR (`\r\r\n`). Fix: write with `newline=""` (byte-faithful; the manager
   already decodes without translation on read).
2. FIXED - FilesystemManager.patch_file reported SUCCESS on a zero-match
   replace: `str.replace` with no occurrence is a silent no-op, so an edit
   that never happened returned success (fabrication vector). Fix: changes==0
   now returns success=False with "old_str not found".
   Additionally edit_workspace was made byte-faithful end-to-end: it decodes
   content WITHOUT newline translation, enforces the exactly-once guard on
   that content, and hands the patched content to write_file_safe - removing
   the LF/CRLF mismatch between guard and delegate that masked defect 2.
- Regression tests added: test_edit_preserves_crlf_line_endings and
  test_filesystem_manager_patch_fails_on_missing_match.
